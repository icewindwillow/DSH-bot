# 架构：增强层，不是另造一个 QQ 宿主

[返回首页](<../README.md>) · [开发指南](<development.md>) · [隐私边界](<privacy.md>) · [生图](<image-generation.md>)

## 谁负责什么

```text
QQ 平台
  ↕ 官方机器人连接、消息与媒体接口
@tencent-connect/dsh-qqbot（上游）
  ↕ 入站门控、会话、提示词、工具与回复
本仓库 qqbot-patches 增强片段
  ├─ 按群人格 / 按说话人角色模块
  ├─ 低打扰唤醒 / 静默 / 主人指令权限
  ├─ 记忆门控 / 可选语义检索
  ├─ 关系、心情、事件、可选日记
  ├─ 媒体归档 / 搜图 / 收藏
  ├─ 可选单张生图（OpenAI / 硅基流动 / Cloudflare）/ 当前 QQ group或C2C 回传
  └─ 模型路由感知的搜索与网页读取
  ↕
DSH 服务与插件（LLM、LTM、工具、调度等）
  ↕
用户选择的模型、搜索及其它外部服务

本机控制台（127.0.0.1:7791）
  ├─ 读取/编辑选定 profile 的配置与状态
  ├─ 保存本机凭据（不回显）
  └─ 通过带 token 的回环控制接口请求会话操作
```

**本仓库拥有的是增强逻辑和运维工具，不是图中每个组件的著作权。** DSH、QQ 插件、LTM 与外部模型服务各自独立；第三方免费模型插件不 vendoring，需用户自行安装。

## 安全启动与独立 overlay

初始化默认只预览；`--apply` 只补缺失的虚构 JSON 和 `dsh-bot.patch.yml`，不修改 profile 包清单或原 `cordis.patch.yml`，不安装宿主/插件。新启动器通过 `--patch` 叠加 overlay，面板也优先编辑它，缺失时才兼容旧 patch。

启动前检查全部补丁、宿主可用性与私有路径，使用启动锁和控制 token，并在 `<profile>/workspace` 工作。profile 必须符合 `DSH_HOME/profiles/NAME` 寻址，profile/workspace 都不能放在本 Git 源码目录。锁只约束使用本启动器的同一 profile，不是对绕过启动器的旧进程的全机排他保证。

跨服务商模型兜底默认关闭，需 `QQBOT_MODEL_FAILOVER=on` 显式启用；启用后需审阅后备 provider/model、Key、上下文外发与计费。Our Free Model 自身 combo 另由插件管理。

## 一条消息经过哪些步骤

1. **判断是否该接话。** 上游接入 QQ 消息，增强门控检查群配置、@、唤醒词、上下文窗口与唤醒指数等条件。被唤醒不保证一定发言，后续仍可静默。
2. **识别当前群与说话人。** 群人格作为底色，说话人的角色模块、话题偏好和成员档案按需参与。名字匹配或跨群合并可能有歧义，不等同于身份认证。
3. **组装上下文。** 加入允许读取的记忆、事件和状态。不是把全部历史永久塞进提示词；同时也不能把逻辑上的 scope 当成访问控制隔离。
4. **调用模型与工具。** 实际会话路由决定主聊天模型；搜索和网页读取沿相应路由执行。辅助判定、卡片、摘要等可能使用单独配置的模型，不能假设全部自动跟随聊天模型。
5. **回传与维护状态。** 回复、图片等经上游 QQ 接口发送，记忆门控和状态维护按各自条件运行。关系、心情是程序状态，不代表模型拥有情感或事实判断一定正确。

## 能力之间的关系

### 群人格与按说话人风格

群人格提供共享语气；说话人模块决定面对当前成员时采用哪些话题、语言风格、角色技能。按需启用比“一张巨大的万能人设”更便于维护，但模型仍可能忽略指令或混淆人物，应允许在面板修正。

### 记忆门控、检索与人物卡

- 门控尝试区分值得记住的信息和普通闲聊，不保证零误记，也不是法律意义上的隐私过滤器。
- LTM 提供长期记忆基础；群 scope 约束常规写入与检索范围。
- 向量模块可选，用自然语言描述找相关旧事；默认关闭，首次开启可能需要下载模型和构建索引。
- 人物卡存在按名字跨群汇总的路径；原始记忆、摘要、人物卡、向量索引不是同一份数据。删除需求要覆盖所有衍生副本。
- 上游默认记忆数据库可能是全局 `~/.dsh/memory/ltm.db`，**换 profile 不等于物理隔离**。

### 关系、心情与事件

关系与心情为可持续状态，事件追踪为后续对话提供线索。它们可能误判，不能用来评价真实成员的人格、健康、风险或信用。日记默认关闭；即使启用本地日记，也必须再次显式授权才可对外发布。

### 媒体与图库

媒体归档、搜索、收藏、发回是不同动作。常规工具按群限制，分享人本人请求自己的图时存在跨群路径；姓名回退匹配、管理员面板与同机文件访问仍有更宽边界。**这不是严格隔离的多租户媒体服务。** 图片识别、搜图、已有图片发送与下方独立的 `generate_image` 生图是不同能力，不能相互冒充。

### 生图：固定后端与本轮授权

生图不跟随聊天 provider；DeepSeek/免费聊天也可单独调用图片 API。模型白名单同时决定服务商、接口地址与凭据（`gpt-image-*` → `OPENAI_API_KEY`，`Kwai-Kolors/Kolors` → `SILICONFLOW_API_KEY`，`flux-1-schnell` → `CLOUDFLARE_API_TOKEN` + 账号 ID）。它默认关闭，由独立 JSON 配置下一调用动态控制，`QQBOT_IMAGE_GENERATION=off` 还可额外禁止，`on` 不会覆盖 JSON 关闭状态。面板仅保存设置，新的 Key 仍靠启动器重启后注入环境。

1. **入站只认原始当前事件。** 使用 `msg.raw.content`，核对原始/规范化消息 ID、作者和群 scope，不取合并消息、引用、历史或 ASR。保守识别明确画图请求，绑定 `stableUserMessageId`、根执行 agent 会话、group/C2C 与原消息 ID；轮次/会话事件撤销授权。自然语言正则不是完整 NLP 语义保证，推荐群 @ 后 `/生图 描述`。
2. **执行守卫与次数限制。** 只接受本轮授权执行，不允许后台、无执行 agent 或跨群调用。每会话冷却/小时上限加进程每小时 10 次硬限制、最多一张在途；失败/取消/不确定 API 尝试计数。内存状态重启清零，不是金额预算。
3. **最小固定请求。** OpenAI 走 `POST /v1/images/generations`（`n:1`、PNG、只读 `b64_json`），硅基流动走 `POST /v1/images/generations`（`image_size`，返回 1 小时有效的 https 图片链接，只下载一次并校验），Cloudflare 走账号作用域的 `/ai/run/`（只有 `prompt` + `steps`，返回 JSON 内 base64 JPEG）。只发本次新 prompt；没有自定义 endpoint、聊天网关、参考图/编辑、批量、付费回退或生图自动重试；请求与读 body 受超时及取消信号约束。
4. **私有暂存与原会话发送。** 校验 base64、PNG 头/尺寸/IEND 和大小，不是完整解码；图片/响应上限分别为 8/12 MiB。图片写入私有 profile 的 `generated-images/request-*`，不入图库、不另存 prompt。发送前再次核对原消息 ID、记录与授权，使用原始 bot 回传，不能由媒体 sender 自动换 ID 或主动推送。
5. **以 QQ 确认为准。** 只有非空 `message.id` 且无失败字段才认定回传成功；否则不声称已发送。QQ SDK 发送没有 AbortSignal，开始后不可保证取消或撤回；等待发送结果再在 finally 尽力清理，不用 Promise.race 提前删图。崩溃/权限错误可能残留，第三方副本不由本机清理保证。

当前适配 QQ 官方插件 0.5.2 的 group/C2C，不宣传频道/dm。完整配置、限制与人工验收见[生图指南](<image-generation.md>)。

### 模型路由、搜索与诚实读取

- OpenAI 会话使用官方 Responses 原生搜索辅助请求；DeepSeek/其它既有路由保留相应的 DeepSeek 搜索路径。
- OpenAI 的网页读取通过专门的原生联网辅助模型完成，不能从聊天模型支持文本推断它支持所有读取工具。
- 辅助搜索/读取不需要转发整段群历史、人设或图片，只发送相应任务所需的查询/URL。
- 原生页面访问必须有目标 URL 对应的完成证据和可读内容；只有搜索结果、引用或其它网页不能冒充成功读取。
- 原生提取不是完整原始 HTML，不伪造 HTTP 200；失败应明确报告，允许有界换源。
- 模型兜底改变实际路由时，下一次工具调用按实际请求上下文决定；不通过修改全局配置让不同群互相抢搜索后端。

## 为什么用补丁，以及代价是什么

增强逻辑插入目标 profile 安装的 QQ/LTM 插件产物，因此对上游结构和锚点敏感。优势是无需分发另一份宿主；代价是每次升级都需要重新验证。

部署工具先对选定范围聚合预检并做语法检查，预检成功后才备份和提交；失败时尝试恢复原件。`--check` 检查片段是否完整，`--revert` 基于真实原件备份恢复，不只是删掉标记。**逐文件原子写入不等于跨文件单一原子事务，更不等于断电恢复保证。**

`--only` 是精确选择，**不会自动补齐依赖闭包**。helper、注入点和工具注册之间有依赖，新手使用完整计划；高级选择必须自行确认依赖已经部署。详见[开发指南](<development.md>)。
