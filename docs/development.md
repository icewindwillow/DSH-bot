## 开发前先划清环境

不要在真实机器人 profile 里做破坏性试验。创建独立测试 profile，使用虚构的群、成员和消息，并在每个终端显式检查 `QQBOT_PROFILE_DIR`。默认长期记忆可能全局共享，测试 profile 不是自动隔离箱；需要测试存储时同时隔离 DSH 数据根并核对各模块路径。

本地观察基线为 DSH 0.2.1-rc.3 / QQ 0.5.2 / LTM 0.3.4；macOS 下 Node 24.22.2 与 25.8.1 均已通过 88/88 离线回归。[CI 矩阵](<../.github/workflows/ci.yml>)已配置 Node 24/25 × Ubuntu/macOS，待推送远端执行，不宣称 Linux 已通过。

```bash
npm install
npm test
npm run security:check
```

命令结果以实际执行输出为准。单元测试通过不能证明真实 QQ 消息发送、上游模型可用性或浏览器行为均已实测。

## 从哪里找实现

| 位置 | 负责内容 |
| --- | --- |
| [patch-qqbot.mjs](<../patch-qqbot.mjs>) | 补丁定义、锚点、依赖顺序、计划、备份、部署与恢复 |
| `qqbot-patches/` | 注入片段与 helper，不是可直接替换整个上游插件的源码 |
| `bot-config-panel/` | 本机 HTTP 控制台、配置编辑、凭据存取 |
| `examples/profile/` | 纯虚构的初始化模板，不包含真实运行资料 |
| `scripts/` | 初始化、环境诊断、机器人启动与仓库安全检查 |
| `plugins/tabletop/` | 可选的本地扩展，与上游 QQ 宿主区分 |
| `tests/` | 回归测试与虚构夹具 |

补丁应保持最小：优先 helper 封装业务逻辑，注入片段只负责明确生命周期和服务接线。不得依赖“某个插件碰巧先加载”，需要的服务应显式声明或使用宿主的待命注入机制。

初始化只补缺失 JSON 与独立 overlay，不改 profile 包清单和原 patch；启动器显式叠加 overlay，面板优先编辑它。启动前完整检查补丁，工作区默认在 profile 下，不能位于本 Git 源码目录。改动此链路时应同时覆盖路径限制、旧配置兼容、锁/token 及凭据优先级测试。

## 安全部署补丁

```bash
npm run patch:plan
npm run patch
npm run patch:check
npm run patch:revert
```

### 预检与部署语义

- 计划聚合预检所有选定补丁，确认目标、锚点和语法；不能发现一处成功就立刻写一处。
- 全部预检成功后才创建原件备份与部署清单，再逐文件提交。
- 失败尝试回滚，恢复使用真实原件，不仅删掉标记；状态/哈希不一致应拒绝不明确的覆盖。
- 同一片段重打应幂等，`--check` 应检测缺失、过时及损坏，而不是“看见标记就算已安装”。
- 备份不得入 Git，不得夹带凭据、群资料或生产日志。
- **不是跨文件单一原子事务，不承诺断电/进程被强杀时全部自动恢复。** 出现不一致时保留部署清单，用本机备份人工核对。

### 精确选择不是依赖解析

```bash
npm run patch:plan -- --only=model-aware-search-inject,model-aware-search-helper,model-aware-fetch-helper,model-aware-search,person-feedback-tool-helper
```

`--only` 精确选择，不自动增加依赖闭包。调用者必须确认 helper、注入点、工具注册与前置补丁已部署或同时选择；目标锚点无法唯一定位时应失败。首次部署不推荐局部挑选。

搜索/读取接管还依赖 profile 选择 `qqbot-model-aware-search` / `qqbot-model-aware-fetch`，停用内置同名 fetch，并保持工具超时预算合理。不得把“一个 helper 可以 import”当作整条集成完成的证明。

### 升级适配

先记录上游精确版本，再在隔离目录验证。核对生成后的整个目标模块，不只看 diff；遇到新版本结构变化应修改匹配和测试，不应放宽到任意替换。QQ、LTM 或宿主升级后都要重跑相应回归与真实验收。

## 测试策略

1. **离线逻辑**：门控、关系状态、事件、scope、权限和模型选择使用虚构输入与可控时间。
2. **失败与负控**：错误档位、缺凭据、同名人物、跨群媒体、缺失/重复锚点、损坏片段和回滚冲突都应有拒绝用例。
3. **HTTP 围栏**：验证 Host/Origin、cookie、控制 token、请求体限制；密钥响应只能返回状态，不能返回值或片段。
4. **本地集成**：使用临时目录和本机桩服务验证完整请求及文件恢复，不访问真实群和公网免费池。
5. **真实验收**：人工授权后运行，明确说明具体 OS/Node/DSH/插件版本、测试了什么、是否实际发送 QQ 消息、是否产生 API 费用。

不要在普通 `npm test` 中顺便探测免费额度或请求官方 API。需要真实联网的测试应独立、显式启用，避免消耗使用者额度或发送不知情的资料。

## 控制台与凭据改动

- 保持仅 loopback、精确 Host/Origin 与 cookie 围栏，不为方便前端开发移除检查。
- 只允许固定凭据字段；状态接口不返回值，不因校验失败把输入拼进错误。
- 保存空白保留，删除显式；非空继承环境优先；修改后标明需要重启。
- `0600` 是权限，不是加密；不要在 UI 宣传“安全加密存储”。
- 重启默认关闭，macOS launchd 必须显式启用并匹配目标，绝不 fallback 拉起第二个实例。
