# 故障排查

[返回首页](<../README.md>) · [部署](<deployment.md>) · [配置](<configuration.md>) · [生图](<image-generation.md>)

先记录本机 **Node / DSH / QQ 插件 / LTM 版本、profile 名和故障发生阶段**，再运行 `npm run doctor`。不要为了排查公开整个 profile、日志、数据库、环境变量或凭据文件。

## 找不到 dsh / Node 不匹配

确认当前终端能运行 `dsh --help` 与 `node --version`。启动器可使用显式 `QQBOT_DSH_BIN` 或 PATH 中的 DSH；以当前版本脚本的诊断提示为准。不要把别人电脑上的绝对路径复制到自己机器。

推荐 Node 24 LTS；本机 macOS 已在 Node 24.22.2 / 25.8.1 通过离线回归，Node 24/25 × Ubuntu/macOS 四组远端 CI 已通过；真实 QQ/API 和 Linux 守护部署仍需另外验收。若原生 SQLite、模型依赖或宿主安装失败，记录精确版本与去敏后的错误，不要承诺换 Node 一定解决。

## init 好像没有改变配置

`npm run init` 默认只预览；写入必须 `npm run init -- --apply`。即使带 `--apply`，也只写缺失模板，不覆盖已有配置。先看它报告的是“缺失”“已存在”还是“目标路径错误”，不要删掉旧文件逼脚本覆盖。

初始化只补缺失 JSON 与独立 `dsh-bot.patch.yml`，不安装宿主/插件，不修改原 `cordis.patch.yml` 或包清单。启动器要求该 overlay；面板启动时优先编辑它，缺失时才兼容原 patch。

如曾对旧 profile 使用 `--from-default-profile web`，那是替换而非合并，应停止写入并找离线备份；初始化不能恢复已经被覆盖的数据。

## 面板显示和机器人实际不同

核对两个进程的 `QQBOT_PROFILE_DIR`、profile 名、启动环境和 DSH 路径。面板默认模型与既有群会话的模型偏好也可能不同，群里 `/model` 需主人权限。

面板修改模型或凭据后需重启。人格/成员配置通常下一轮重读，但不保证改变正在生成的一轮回复。

## 路径不匹配 / workspace被拒绝 / 启动锁存在

启动器要求 `QQBOT_PROFILE_DIR` 严格等于 `DSH_HOME/profiles/QQBOT_PROFILE_NAME`；要改数据根，请统一设置 `DSH_HOME` 并在该根创建真实 profile，不能只把目录指到任意位置。profile 和 workspace 均不得位于 Git 源码目录，默认 workspace 为 `<profile>/workspace`。

发现锁时不要立即删：先确认旧机器人和守护进程全部退出，再在本机核对是否为残留锁。锁不能阻止绕过启动器的其它实例。启动器也会检查全部补丁；缺失/过期时先停机预检修复，不跳过检查强行启动。

## 密钥保存了却仍报鉴权失败

- 使用 `npm run bot` 启动，确认启动器会加载所选 profile 的 `.bot-secrets.json`。
- 面板接口只返回已配置/来源，不验证账号余额、权限和网络。已配置不等于可调用。
- 非空环境变量优先；面板写入新值不覆盖启动环境里的旧 Key。
- 留空表示保留，显式删除仅删除本地值，不能清除继承环境变量。
- QQ 应用凭据和模型 Key 是不同用途，确认填在正确字段。

不要打印 Key 或在群里贴错误请求头。怀疑泄漏时先轮换，见[安全报告说明](<../SECURITY.md>)。

## 面板 401 / 403 / 打不开

使用终端打印的 `http://127.0.0.1:7791`，不要改域名、端口或 IP，也不要通过网页代理/公网反代访问。

- 401：先在同一浏览器打开面板页面以获得本次进程的 HttpOnly / SameSite cookie；重启面板后旧 cookie 可能失效。
- 403：检查是否换成了 `localhost`、局域网地址、异源请求或不允许的 Host/Origin。这是安全检查，不应删掉。
- 端口占用：确认是不是另一份面板在跑，停止不需要的实例或按支持的端口参数配置；浏览器地址也要跟着变化。

本机恶意进程不由这些围栏完全隔离。不要把关闭安全检查当作修复方案。

## 重启按钮不可用 / 提示已请求但没 ready

默认禁用是预期行为。手动管理时先停止原机器人，再运行 `npm run bot`；有守护时必须从原管理器操作，不要手动叠一份。

只有 macOS 且显式 `QQBOT_PANEL_RESTART=on`、`QQBOT_LAUNCHD_LABEL` 与所选 profile 匹配时才调用 launchd。找不到任务或平台不符就报错，绝不会 fallback 新进程。“已请求”不等于“已就绪”，在本机检查原任务日志。

## Invalid gateway session / 频率限制 / 反复断线

优先检查是不是同一个 QQ AppID 被两个实例使用：终端、launchd、旧脚本或另一台电脑都有可能。不要反复点重启扩大连接冲突，也不要把所有 429 都当重复实例——平台和模型本身也有限流。

确认旧实例已停止后只保留一份；敏感 ID 仅本地核对，不公开贴进 Issue。

## 机器人不回 / 太吵

- 测试时先明确 @，确认 QQ 平台权限、群配置和就绪状态。
- 检查是否需要唤醒词、群是否允许免 @、唤醒指数是否过低，以及是否触发静默。
- `/new`、`/compact`、`/model` 等管理命令受主人名单限制，空名单时被忽略不是模型故障。
- 太吵时降低唤醒指数，审查自动表情、事件和主动回应条件；明确 @ 可能绕过随机门控。
- 已经开始生成但无回应，还需检查模型额度、超时、工具失败，而不只调整唤醒值。

## 推理档位报不支持

模型自身档位、默认模型档位和路由统一档位不是一回事。混合路由里若有不支持该档的模型，请清空统一路由档位，按模型分别设置。免费模型清单可能变动，不要把另一家相同模型名的档位照搬。

## 免费模型消失 / 达限额 / 地区受限

免费清单、网络出口和配额受上游控制。去 Our Free Model 自己的设置检查来源、地区、错误和可用性；不要通过无限重试消耗额度或规避条款。新上游故障不代表本项目可以保证修复，必要时选择自己有权限的付费 API。

免费渠道失败后默认不会跨服务商兜底。确实需要时，先评估上下文外发和费用，再显式 `QQBOT_MODEL_FAILOVER=on`，配置后备 provider/model、路由及 Key。Our Free Model 自身 combo 另由插件管理。

如果安装自 npm 同名包，先核对官方说明：上游明确不认可该分发，按[免费模型指南](<free-models.md>)从官方 Release/可信源码安装。

## 搜索能用，但文章读不到

搜索摘要与网页原文是两种证据。OpenAI 原生读取必须有目标 URL 的完成访问和可读内容，不能拿其它页面、引用或摘要冒充全文；它也不提供可靠的原始 HTTP 状态或完整 HTML。

检查模型感知 helper、注入、provider 配置与内置 fetch 停用是否一起部署。OpenAI 辅助请求需要相应凭据、权限和费用，失败不会悄悄改用另一家服务商冒充成功。

单页失败可有界换其它公开来源；指定文章仍读不到时请提供正文/截图。不要无限重试同一失败 URL，也不要为修一个站点改全局服务商端点。

## 生图没有触发或没有收到图片

先看[生图指南](<image-generation.md>)，不要靠反复调用来测试余额，也不要把主聊天模型切到 OpenAI 当作必需修复。

- **未启用 / 找不到工具**：确认当前 profile 已部署全部相关补丁，且面板“OpenAI 生图”中 `enabled:true`。默认关闭是预期行为；`QQBOT_IMAGE_GENERATION=off` 会额外禁止，`on` 不会越过 JSON 的关闭状态。
- **消息没被授权**：在当前会话重新发送完整明确的 `@机器人 /生图 一只看星星的鲸鱼`。不要引用旧请求，不用历史、合并队列内容或语音转写代授权。原始 QQ 当前消息 ID、作者/群与执行会话必须一致；只支持官方插件 0.5.2 的 group/C2C，不宣传频道/dm。自然语句是保守正则识别，不能保证理解所有否定或引述。
- **Key 已填却鉴权失败**：新 Key 需要停止旧实例并用 `npm run bot` 重启；非空继承环境仍优先。生图固定用 OpenAI 官方接口，不经过自定义聊天网关；聊天网关可用不代表官方 Key 有效。模型权限和额度要在自己的官方账号核对，不贴 Key、请求头或原始响应排查。
- **设置保存失败 / 状态读不出**：配置必须完整七字段，不能加 URL、`prompt`、`n` 等字段；数值必须是范围内整数。检查 16 KiB 文件上限、私有目录权限及链接拒绝规则，不删除安全检查绕过。模板见[公开默认配置](<../examples/profile/qqbot-image-generation.json>)。
- **模型或参数不支持**：只使用面板白名单；已下线 `gpt-image-1` 和 DALL·E 不接受。工具限定的三种尺寸不是 API 最大能力声明；白名单也不保证账号都有权限。
- **冷却 / 小时上限 / 已有在途请求**：每会话限制之外，进程每小时最多 10 次尝试，同时最多一张。失败、取消、结果不确定的 API 尝试也计数；请等待，不自动重试。重启清零是内存限流的局限，不是规避额度或费用控制的办法。
- **生成了但不投递**：若原消息、记录或授权已经变化，生成完成后仍可能拒绝发送；这时可能已经计费。QQ 返回错误、空确认或没有非空 `message.id` 时不能说已发，不使用其它群、主动推送或自动换消息 ID 来补发。
- **超时 / 取消后结果不确定**：API 与 body 读取受 `30..300` 秒超时约束；QQ SDK 发送阶段不可由 AbortSignal 取消。SDK 已开始发送后不能保证撤回，图片可能稍后出现；客户端报错也不证明上游未收费。不要自动重新生成。
- **响应被拒绝 / 临时文件残留**：只读 base64 PNG，不接收下载 URL；图片最多 8 MiB、响应最多 12 MiB，基础 PNG 结构检查不是完整解码。发送完成/失败后尽力删除；崩溃或权限错误可能留下 `generated-images/request-*`。确认没有在途发送后再本地审查，不要边发送边删图或上传残留来求助。

真实 QQ/API 验收须管理员自行授权并承担可能的费用；离线 mock 通过不等于成功调用真实付费服务。

## patch:plan / patch:check 失败

- 先核对观察基线：DSH 0.2.1-rc.3、QQ 0.5.2、LTM 0.3.4。
- 核对目标 profile 的实际安装位置；`npm install` 本仓库不等于给 DSH profile 装好了插件。
- 上游升级/重装会覆盖产物，需重新预检和部署；锚点变化应停止适配，不强行替换。
- `--only` 不补依赖，缺 helper/注入点要自行补齐或重新做完整计划。
- `--check` 发现片段过时或损坏时，不要只补一个标记骗过检测。

执行恢复前停止机器人，运行 `npm run patch:revert`。若哈希冲突说明文件被其它流程改动，保留备份和部署清单，本地比较；不要无条件覆盖，更不要将生产备份上传。逐文件回滚不是断电事务保证。

## 记忆串群 / 关了功能仍找得到内容

上游记忆数据库默认可能全局共享，群 scope 不是安全边界；人物卡存在跨群汇总路径。关掉门控、人物卡或向量只停止后续处理，不删除已有摘要/人物卡/索引/备份。

先停用相关任务，再按[隐私说明](<privacy.md>)核对全部副本。不要只删一条原始记忆就假设衍生内容和外部模型端记录都消失。

## 提交问题前

提供：复现步骤、期望/实际行为、精确版本、使用虚构数据的最小示例、去敏错误类型，以及做过哪些检查。明确区分离线测试、本地桩、真实 QQ、真实 API。不要上传真实群消息来证明机器人“说错了”。
