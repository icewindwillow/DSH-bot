# 隐私与数据边界

[返回首页](<../README.md>) · [安全报告](<../SECURITY.md>) · [配置开关](<configuration.md>) · [生图边界](<image-generation.md>)

**部署前请先向群成员说明：机器人可能把消息发送给外部模型，并在本机留下长期状态。能收到一条消息，不等于获得无限收集和公开它的授权。**

## 可能处理哪些数据

| 数据 | 用途与位置 | 风险 |
| --- | --- | --- |
| 群消息、发送者和会话标识 | 上游会话、群资料及模型上下文 | 可能含姓名、联系方式、情绪或私人事件 |
| 成员档案、关系、心情、事件 | 所选 profile 的运行状态 | 模型推断可能错误；不宜当作真实人物标签公开 |
| 长期记忆、摘要、人物卡 | 上游 LTM 数据库及相关衍生记录 | 可能长期保留并出现跨群汇总 |
| 向量索引 | 开启后在本机生成语义检索索引 | 仍由原始记忆派生，不因不可直接阅读就不敏感 |
| 图片、描述、收藏 | profile 下媒体目录与索引库 | 图片和描述都可能识别个人、位置、账号或作品作者 |
| 生图 prompt 与生成图片 | 启用后 prompt 发给所选服务商（OpenAI 或硅基流动），图片暂存 profile 的 `generated-images/request-*` 后回传当前 QQ 会话 | prompt 可能含隐私，图片/请求可能由第三方留存；本机尽力清理不等于第三方删除 |
| 日记 | 开启后的本地日记和可选发布输出 | 文学化/匿名化仍可能泄露上下文 |
| 凭据 | profile 的 `.bot-secrets.json` 或进程环境 | 本地明文，不能入 Git/截图/日志 |
| 日志与备份 | 本机日志、配置备份、补丁备份 | 可能保留已删除的旧资料、路径、标识或密钥 |

这不是完整磁盘清单。DSH、QQ 插件、LTM 与第三方插件还可能拥有自己的状态目录和日志；请一起审阅。

## 谁会收到消息内容

主聊天模型服务会收到本轮上下文，可能包含用户消息、选入的记忆、工具结果、角色设定与图片。辅助判断、摘要、人物卡等可能调用其它模型，其服务商不一定等同于主聊天模型。

本项目的跨服务商模型兜底默认关闭，只有 `QQBOT_MODEL_FAILOVER=on` 才启用。启用后，失败回合的上下文可能被发送到另一个后端并收费；应显式检查 `QQBOT_FALLBACK_PROVIDER` / `QQBOT_FALLBACK_MODEL`、路由 Key 和服务商条款。Our Free Model 自身的 combo 是另一套插件管理的降级链，仍要单独审阅。

机器人工作区和 profile 位于仓库外，启动器使用独立 overlay、私有锁与 token；这些措施降低源码目录混入运行数据的风险，不是同机进程或多群隐私隔离。

搜索与网页读取通常只需要查询或 URL，不应为了查一个链接附带整段群历史。但**查询词和 URL 本身也可能包含隐私**，例如带 token 的分享链接或私人项目名称。

免费渠道不代表私有服务。Our Free Model 的官方说明披露，部分 Kilo 免费模型可能记录提示词用于改进服务；未来来源和条款也可能改变。请勿通过免费渠道发送密码、API Key、身份证明、商业机密或任何不愿外部服务处理的数据。安装前读[免费模型说明](<free-models.md>)和对应上游条款。

## 生图：单独外发，不因聊天免费而免费

生图默认关闭，须主动启用、配置对应服务的 Key，并由当前真实 QQ group/C2C 消息的明确请求授权。聊天模型可以是 DeepSeek 或免费模型，图片请求仍发往所选模型的固定官方接口（OpenAI 或硅基流动），可能独立计费（Kolors 当前免费），不经自定义聊天网关。硅基流动会返回一个 1 小时有效的图片链接，本工具只下载一次，不转发该链接。

图片请求只发送本次新 prompt 与必要生成参数，不自动附带群历史、参考图、记忆或人设；**prompt 本身仍可能含私人内容，且主聊天模型仍按既有会话流程处理上下文**。不要把“不附历史”解释为整条聊天链路都不出网，也不要代别人发送敏感描述。

授权核对原始 QQ 当前事件、消息 ID、作者/群 scope，并绑定当前执行会话，避免借合并消息、引用、历史或其它群上下文付费。自然请求由保守正则识别，不是完整语义理解或绝对防误触保证；推荐明确 `/生图 描述`。模型可见上下文不因此成为生图授权来源。

生成 PNG 只暂存在私有 `generated-images/request-*`，目录 `0700`、文件 `0600`，不加入图库，不另存 prompt。发送完成/失败后立即尽力删除，但崩溃、强杀、权限或磁盘问题可能残留。PNG 仅做 base64、头/尺寸/IEND 和大小检查，不是完整解码或内容安全审核。管理员在确认没有在途发送后还应审阅残留与备份。

只向当前授权 QQ 会话回传，不承诺从 QQ、OpenAI、聊天服务商、备份或群成员客户端删除副本。发送前若轮次/授权已变化，会停止投递，但生成可能已计费；QQ SDK 已开始发送后也无法保证撤回。失败、取消或不确定结果不能作为“没有费用”的证据，次数限流不是金额预算。完整边界见[生图指南](<image-generation.md>)。

## 重要：群 scope 和 profile 都不是严格安全边界

1. **上游记忆数据库默认可能全局共享**，例如 `~/.dsh/memory/ltm.db`。新建 `qqbot-demo` 并不会自动把旧 `qqbot` 的长期记忆物理分开。
2. 群 scope 用来约束常规记忆写入和检索，是应用逻辑约定，不是数据库权限、沙箱或多租户隔离。
3. 人物卡有按姓名读取多个群近况/偏好并汇总的路径，可能把多个群的信息合并。姓名重名、同名匹配和身份回退还会带来误关联。
4. 部分模型/工具上下文和管理界面可以看到更广的数据。管理机器的用户也可直接读取文件。
5. 媒体工具默认按群过滤，但分享人请求自己的图时有跨群访问路径，身份可能通过档案姓名回退识别。管理面板本身可查看所选 profile 的图库。

因此**不要宣称本项目实现了严格群隔离或多 profile 物理隔离**。有强隔离要求时，优先采用不同操作系统账号、独立 DSH 数据根与经核实的独立数据库配置，检查每条后台任务和衍生存储路径；仅改 `QQBOT_MEMORY_DB` 不能证明上游 LTM 与所有辅助模块已经一致隔离。

## 默认不开启日记与向量

- `QQBOT_DIARY` 默认 `off`；启用后可能产生本地日记。
- 对外发布还需要 **`QQBOT_DIARY_PUBLISH=on` 和明确的目标 ID**。启用日记不等于授权发布；请先本地预览并获得涉及成员同意。
- 匿名、改昵称、第一人称改写不保证隐私。时间、地点、事件组合、图片和习惯表达仍可能重识别个人。
- `QQBOT_VECTOR` 默认 `off`；启用后需下载/加载本地嵌入模型并建立索引。模型下载源、运行权限和索引备份同样要纳入审核。

`QQBOT_MEMORY_WRITE=off` 限制模型主动调用受保护的写记忆工具，**不等于关闭自动门控及所有后台数据库写入**。这些默认关闭项不是对其它已开启模块“无隐私风险”的保证。敏感场景还应审阅人物卡、事件、记忆门控、日志与收图配置。

## 本机控制台能防什么，不能防什么

控制台只监听回环地址，检查 Host/Origin/同站来源，使用 HttpOnly、SameSite cookie；机器人内部控制口还需要 token。这些措施用于降低跨站网页和误暴露风险，**不等同于用户登录系统或同机进程隔离**。

同账号进程、本机管理员、浏览器恶意扩展及可读备份的人仍可能接触数据。不要开放到公网，不要关闭围栏让反向代理“能用就行”，也不要把本机 session cookie、控制 token 或凭据文件分享到别人电脑。

## 最小收集建议

- 先说明用途、接入哪些模型及可能的本地保存，再邀请成员测试。
- 从主动 @ 和低唤醒指数开始，不追求每句话都接。
- 只记录与互动确实相关、获得同意的信息；不要自动整理健康、财务、未成年人、身份或第三方敏感信息。
- 收图只针对明确同意的成员与内容；避免把相册当作无条件抓取工具。
- 日记发布采用单独授权、预览与随时关闭机制。
- 定期清理无用状态、旧日志与备份，保留清晰的删除流程。

## 删除与退出

关闭功能只停止后续处理，**不自动删除历史数据**。处理成员删除请求时：

1. 停止相关后台任务和机器人写入，备份仅用于受控恢复，避免继续传播。
2. 核对档案、关系/心情、事件、长期记忆、人物卡、摘要和向量衍生记录。
3. 核对媒体文件、索引、描述、收藏、生图临时目录残留、日记、会话与日志；删除生图残留前确认无在途发送。SQLite 操作需理解数据库一致性与 WAL。
4. 检查离线备份、云盘同步、旧电脑及公开发布副本。外部模型已接收的数据按服务商规则处理，本项目不能代其保证删除。
5. 重新验证检索和人物卡不会又从其它旧副本补回已删除内容。

本仓库不提供对第三方副本或已发布群消息“完全擦除”的承诺。不确定如何清理时先停用相关功能，而不是把真实数据库上传来求助。

## 公开仓库不应出现什么

密钥、真实群与成员 ID、可识别成员资料、聊天历史、运行日志、私有图片、数据库、凭据备份和生产配置均不得入库。示例与测试只用纯虚构资料，不用“简单去掉群名”的真实记录。安全扫描是辅助，不是证明没有泄漏的证书。
